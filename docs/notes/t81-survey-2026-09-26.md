## 0. いま変換器が受け付けるもの（2026-09-26 の実装を読んで）

- **model_type**: `llama`・`qwen2`・`gpt2`・`gpt_neox` の 4 つだけ（`check_config()`）。
- **形**: `head_dim` は `hidden_size / num_attention_heads` と同じで偶数であること。GQA は llama と qwen2 だけ。
- **活性化関数**: llama と qwen2 は `silu` だけ。gpt2 は `gelu_new`・`gelu`・`gelu_pytorch_tanh`（**`gelu_fast` は通らない**）。neox は加えて `gelu_fast` も通る。
- **bias**: qwen2 の q・k・v だけ。llama の `attention_bias` と `mlp_bias` は断る。
- **RoPE の縮め方**: `rope_scaling` があるなら、llama 系で `llama3` の種類のときだけ通る（linear・dynamic・yarn・longrope は断る）。transformers 5 の `rope_parameters` は `normalize()` が古い名前に直す。
- **sliding window**: `use_sliding_window` が真なら断る（qwen2 の config にある `sliding_window` の値そのものは見ない）。
- **トークナイザ**: `tokenizer.json` の Unigram、byte-level BPE（前分割は `gpt2`・`gpt2-digits`・`qwen`・`llama3` の 4 つ。Metaspace・Whitespace・知らない Split の正規表現・`add_prefix_space` は断る）、sentencepiece の `tokenizer.model` / `spiece.model`（unigram か BPE）。`?hf=` のときは tokenizer.json を先に試し、断られたら tokenizer.model を試す（worker.js）。
- **ファイル**: safetensors は 1 ファイルでも、index の付いた何シャードでもよい（T105）。dtype は F32・F16・BF16 だけ。**使うテンソル**の dtype だけを見るので、GPT-2 と NeoX の U8 / BOOL の attention mask（`attn.bias`）は害がない。GGUF は `llama` と `qwen2`、F32・F16・Q8_0 だけ。語彙は byte-level BPE で、前分割は `gpt-2`・`smollm`・`qwen2`・`llama-bpe`。`rope_freqs` の表を持つ GGUF（Llama 3）は断る。
- **32 の倍数**: dim・kv_dim・hidden が 32 の倍数でないと int8 のカーネルに乗らない（断られはしないが、float32 に広がって遅く大きい）。int6 はそういう行があると断る。今回見た実物のモデルで 32 の倍数でないのは、テスト用の極小モデル 17 件だけだった。
- **メモリ**: 自動のときは、int8 が forward の分（`footprint()`）と合わせて 32 ビットのメモリ（4GiB）に入れば int8、入らなければ int6（`automaticBits()`）。int6 でも入らなければ 64 ビットのメモリ（最大 16GiB、Chrome と Firefox だけ。Safari では断る）。**だから 7〜8B は int6 で 64 ビットのメモリに載る**。
- **テンプレート**: `tokenizer_config.json` の `chat_template` だけを読む。**`chat_template.jinja` は読まない**。

## 4. RoPE の縮め方と sliding window

- 受け付ける 4 種類の 438 件: 縮めなし 368、**llama3 66**、linear 3（deepseek-coder 1.3b・6.7b-base・6.7b-instruct）、yarn 1（gpt-oss-120b の Eagle3 の下書きモデルで、ほかの理由でも断られる）。1.5B 以下の 181 件では llama3 17・linear 1・yarn 1、3.5B 以下の 267 件では llama3 23・linear 1・yarn 1。
